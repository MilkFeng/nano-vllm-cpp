# FP32 GEMM 性能报告

GPU：NVIDIA GeForce RTX 5060 Ti，SM 12.0，36 SM，显存 15.90 GiB，L2 32.0 MiB。

CUDA runtime 13030，driver API 13040，cuBLASLt 130600，nvcc 13.3.73，Release 构建。CPU/驱动快照和源码、二进制 SHA256 见 `manifest.json`。

完成 3 次独立进程运行，每进程每实现 15 组 event 样本，目标每组 10 ms，最多 1024 次 GEMM；每项预热至少 20 次或一次完整轮换。seed 分别为 42, 43, 44。

## 口径

- `X[M,K] @ W[N,K]^T`，FP32 输入、累加、输出，alpha=1、beta=0，无 bias。
- CUDA Graph + CUDA events 测 GPU 执行，不含分配、H2D、CPU 提交、handle/descriptor 初始化及算法选择。
- 主流对照为严格 FP32 SGEMM 与严格 FP32 cuBLASLt 调优结果的逐 case 较快者。二者使用 32 MiB workspace；Lt 最多返回并实测 8 个启发式候选，各用独立的 3 组校准样本选算法。
- 原默认算法、零 workspace 的 cuBLASLt 仍单列为 legacy，主结论不使用它替代更快的严格 FP32 对照。
- CUDA 分块基线为 16×16 block、K tile=16、每线程一个 FP32 累加器；使用共享内存，W 的 shared tile 加一列 padding。它不是未优化的朴素点积。
- hot 表示重复使用同一组矩阵；rotating 轮换最多 256 组地址，目标工作集为 max(64 MiB, 2×L2)。未达到目标的 case 明确标注，轮换测试不宣称每次访问都为冷缓存。
- 每进程先取 event 样本中位数，再取进程间中位数；对各 shape 加速比做等权几何平均。进程范围为每个独立进程几何平均的最小值和最大值，不是置信区间。
- 每个 shape 各实现全量输出与 SGEMM 比较，并检查最多 1024 个独立 FP64 点积。容差为 |error| <= 2e-4 + 2e-4×|reference|。另通过 180 组生产 kernel 和 30 组分块基线检查。
- 结果涵盖预先声明的完整 shape 集；不等价于整模型 prefill/decode 加速，且不与 TF32/FP16 Tensor Core 路径混比。

## 可用于简历的表述

以下为完整测试范围的限定表述，不将最好的一项扩展为整体收益。

> 实现 FP32 CUDA GEMM/GEMV，采用寄存器分块、float4 向量化、共享内存双缓冲、寄存器预取与 XOR swizzle，支持 X@Wᵀ 并按 M 分派；在 NVIDIA GeForce RTX 5060 Ti、33 种预定义尺寸的 hot 测试中，吞吐几何平均为 16×16 共享内存分块基线的 2.63 倍、严格 FP32 cuBLAS 对照的 70.2%，峰值 9.85 TFLOPS；通过数值一致性检查。

> 实现 FP32 CUDA GEMM/GEMV，采用寄存器分块、float4 向量化、共享内存双缓冲、寄存器预取与 XOR swizzle，支持 X@Wᵀ 并按 M 分派；在 NVIDIA GeForce RTX 5060 Ti、33 种预定义尺寸的 rotating 测试中，吞吐几何平均为 16×16 共享内存分块基线的 2.15 倍、严格 FP32 cuBLAS 对照的 64.2%，峰值 9.71 TFLOPS；通过数值一致性检查。

## 原始证据与复现

- `run-*.json`：每组原始耗时、采样顺序、算法校准、误差、调用次数与工作集。
- `run-*.log`（归档为 `run-*.txt`）：进程输出。`manifest.json`：完整命令、系统、GPU 快照、git 状态、源码与二进制 SHA256。
- `memcheck.txt` / `racecheck.txt`：归档的内存与同步检查日志。`summary.json` 另记录当前报告生成脚本的 SHA256。
- `summary.csv` / `summary.json`：完整逐项与分组数据，可用表格工具继续分析。
